## A machine of its own

Prepare a Linux machine with Docker and at least 100 GB available for document storage. Options include a small fanless N100-class box, a NUC, a Raspberry Pi 5 with an SSD, or a rented VPS. The guides were written against **Debian 12 (bookworm)**, minimal, with SSH, and that is what the installer is tested on.

<Note label="One rule">

Do not run Harbor on the machine that is also your firewall or router. If your fanless box runs OPNsense or pfSense, the vault gets a box of its own.

</Note>

## Free disk for the data volume

Everything Harbor stores, documents, database, queues and secrets, lives in one directory, `/data` by default. That directory must sit on an encrypted volume, because the database keeps the text of every document in the clear so that search is fast. The installer checks this and refuses to continue otherwise.

A second disk is the simplest way. If `/data` is not encrypted, the installer offers to turn a spare disk into the encrypted volume: it lists the disks, asks which one, makes you type its name to confirm, erases it, and asks how the volume should unlock after a reboot. It never offers the disk the system boots from. It generates the volume's passphrase and tells you where to find it for [the envelope](/docs/break-glass).

If the machine has only one disk, leave at least 100 GB unallocated during the operating system install and set up the volume by hand before you run the installer. [The data volume](/docs/data-volume) walks through formatting it.

## How you will reach the vault

The installer asks. Tailscale is optional; it is the easiest path and the one these guides describe first, but each option has different access and configuration requirements:

- **Over your tailnet.** With Tailscale on the host, the vault is reachable only from your own devices, over HTTPS, with nothing listening on the machine's own network interfaces.
- **On your own network.** The vault publishes a port on an address you choose, for example the machine's LAN address. No separate network-service account is needed. Devices on that network can reach the sign-in page.
- **A VPN or mesh you already run, or headscale.** Harbor treats a VPN address like your own network, and headscale works with the Tailscale path unchanged.

[Reaching your vault](/docs/reaching-your-vault) lays out all of them.

For the tailnet you need a Tailscale account; you can create one when you sign in. If Tailscale is not on the machine, the installer offers to install it with the official script and sign the machine in: it prints a link, and you open it on any device and sign in. One step it cannot do for you: in the Tailscale admin console, under DNS, enable HTTPS Certificates, so the vault has a certificate to serve. The installer waits while you do.

To install Tailscale yourself instead, before running the installer:

```sh
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
```

## Somewhere for backups to go

The installer's third question. A Backblaze B2 bucket, an SFTP host you already have, or a second disk in the same machine. [Backups](/docs/backups) explains the three options; decide before you run the installer, or leave it unset and configure it afterwards.

## A printer, at the end

After setup, print the recovery information described in [The break-glass envelope](/docs/break-glass). Keep it separate from the server.
